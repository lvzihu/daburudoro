## Why v3 contains several correction commits

V3 was tested as a release candidate before it was merged. Each round exposed a
more precise visual or interaction requirement, and each correction was
committed separately on the same feature branch:

1. `bd46c39` — add companions and Break music.
2. `b4a5f84` — animate real character frames instead of disconnected vectors.
3. `f3636f0` — lock animation to activity regions.
4. `e494721` — rebuild motion around working hands and props.
5. `4a9212e` — polish the accepted visuals, sleeping `Z`s, hide cross, and
   vertical progress.
6. `63fa1f7` — remove Green's synthetic finger and make picker clicks stable.

The matching `docs:` commits link the implementation to dated requirements and
acceptance records. Keeping these commits visible makes the product-learning
loop inspectable in GitHub instead of presenting v3 as if it appeared in one
perfect attempt.

## Versioning interpretation

These are pre-release review corrections, so the accepted release remains
`3.0.0`. A bug discovered after publication would normally be fixed from
`main` and released as `3.0.1`; a backward-compatible feature would become
`3.1.0`; a breaking product change would become `4.0.0`.
